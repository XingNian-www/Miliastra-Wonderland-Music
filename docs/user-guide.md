# 用户使用指南

## 1. 首次运行

运行前请确认：

- 使用 Windows，并让游戏画面分辨率与配置中心 `window` 段中的坐标配置相符。
- 游戏已经安装，且配置中心 `window.target_process` 填写了正确的进程名。
- 截图采集方式默认是 `window.capture_method: gdi`；遇到黑帧、遮挡或独占全屏问题时，按下文逐项测试。
- 播放器由主程序提供，不需要单独启动播放器进程。
- 登录功能需要系统已安装 WebView2 Evergreen Runtime；发布包中的运行资源位于 `deps/`。
- 程序以管理员权限运行，这样才能操作游戏窗口和发送按键。

### Windows 截图采集方式

在 Web 面板的“配置中心”中展开“窗口”配置，选择 `window.capture_method`。这是配置数据库中的运行参数，不写入启动引导文件 `config.yaml`。修改后需等程序空闲并重载配置；如果当前版本未热重载该项，则重启程序。所有方式都会输出目标窗口客户区，并继续使用现有分辨率缩放、OCR 和模板匹配流程。

| 配置值 | 采集原理 | 优点 | 局限与适用场景 |
| --- | --- | --- | --- |
| `gdi`（默认） | 从游戏窗口 DC 调用 GDI `BitBlt` 读取客户区 | 系统自带、无需额外 DLL；开销低；普通窗口和无边框窗口通常兼容；不要求游戏窗口位于前台 | 被其它窗口遮挡、最小化或使用独占全屏时可能得到遮挡内容或黑帧；这是现有默认方式 |
| `print_window` | Windows `PrintWindow(PW_CLIENTONLY)` 请求游戏窗口自行绘制到位图 | 某些应用即使被遮挡也能返回完整客户区；不依赖屏幕上窗口区域当前显示的像素 | 绘制发生在目标进程内，响应可能更慢或阻塞；许多硬件加速游戏不实现该绘制路径，可能返回黑帧；成功返回也不代表图像有效。适合作为被遮挡时的尝试，不保证支持 |
| `desktop` | 从桌面 DC 按窗口客户区屏幕坐标 `BitBlt` 裁剪 | 采集语义最直观，得到的就是桌面当下可见内容；便于验证遮挡、窗口位置和显示器输出问题 | 必须保证整个游戏客户区可见、未被遮挡且未最小化；遮挡物会一起进入图像；独占全屏/受保护内容仍可能不可读。适合窗口化排障 |

建议顺序：先用 `gdi`；遇到遮挡导致画面缺失时试 `print_window`；若想确认屏幕上实际显示了什么则用 `desktop`，并让游戏窗口完整可见。切换后用面板实时截图或 OCR 预览检查整帧是否正常，不要仅凭截图调用成功判断。三种 GDI 系方式都不能保证捕获 GPU 独占全屏或受保护的视频表面；这不是更改配置就能绕过的限制。

启动程序后，默认会进入常驻值守。首次使用按 [简易配置流程](../README.md#简易配置流程) 打开 Web 面板并填写访问令牌，再确认游戏窗口、OCR 和播放器状态。

## 2. 启动游戏与进入千星

在配置中心启用 `startup.enabled` 后，可以分别开启：

- **启动游戏**（`startup.launch_game`）：程序启动时查找游戏窗口，找不到时启动游戏。
- **自动进入游戏**（`startup.enter_game`）：持续未知满 5 秒后，OCR 识别到“点击进入”并确认大门界面，自动执行进入游戏流程。游戏自动重启后也会继续检测。
- **自动进入千星**（`startup.enter_wonderland`）：同一检测阶段未发现“点击进入”时，匹配右上角祈愿图标；确认主世界后自动执行进入千星流程。

正常一级、二级界面不会执行这两项补充检测。大门界面和主世界会显示在面板的界面状态中；关闭自动开关时只显示状态，不执行进入操作。自动进入前会重新确认当前画面，任务结束后至少等待 5 秒再尝试。

Web 面板也可以手动提交以下任务：

- **启动游戏**：查找已运行的官服/国际服窗口；找不到时按 `startup.exe_path` 尝试启动，进入游戏主界面后结束。
- **进入千星**：从游戏主界面按 `M` 打开地图，匹配右下角星型入口并点击；地图侧栏打开后，在右侧选项区域 OCR 查找包含“千星奇域”或“大厅”的选项并点击，随后匹配并点击“确认”，完成后停留在可继续操作的界面。

自动进入千星没有找到入口时，可在 Web 高级工具页选择“祈愿”检查匹配结果，并确认游戏分辨率与配置一致。

## 3. 聊天命令格式

大厅命令来自蓝色聊天消息，好友私聊命令来自粉色聊天消息。例如，在大厅发送 `@点歌晴天`，在好友私聊发送 `@麦克风`。

命令名与参数之间不依赖空格分隔，OCR 空白可能增加或丢失；下表命令名与参数之间的空格只是排版占位，可省略。黄色标识只用于辅助识别聊天，不是命令来源。`@帮助` 显示点歌帮助，`#娱乐` 或 `@娱乐帮助` 显示娱乐玩法帮助。

| 命令 | 作用 |

| `@AI点歌 歌名 歌手`、`@AI搜索 歌名 歌手` | 搜索候选后由 AI 选择 |
| `@QQ点歌 ...`、`@QQ搜索 ...` | 强制使用 QQ 音乐 |
| `@网易点歌 ...`、`@网易云点歌 ...`、`@网易搜索 ...` | 强制使用网易云音乐 |
| `@酷狗点歌 ...` | 使用酷狗音乐 |
| `@B站点歌 关键词`、`@B站搜索 关键词` | 好友私聊，或大厅内已映射为好友及以上身份的成员使用 B 站来源 |
| 好友私聊 `@点歌 BV1GJ411x7h7` | 识别为 B 站视频号并直接播放 |
| `@暂停` | 暂停当前播放 |
| `@继续`、`@恢复`、`@播放` | 继续播放 |
| `@下一首`、`@下一曲` | 播放下一首 |
| `@上一首`、`@上一曲` | 播放上一首 |
| `@音量 30` | 设置 0 到 100 的音量 |
| `@状态` | 查询播放器状态 |
| `@大厅检测` | 读取当前大厅名称 |
| `@大厅时间` | 查询已记录的大厅剩余时间 |

如果搜索结果不唯一，机器人会提示 `@确认`、`@跳过`、`@换源` 和 `@AI`；平台没有找到音源，或本地曲库记录的匹配度比在线结果更高，还会提示 `@本地`。本地兜底会跨所有音乐源查找记录，不受本次点歌指定的音乐源限制；B 站来源仍只对好友及以上开放，即好友私聊，以及在大厅被映射为好友、管理员或主人的成员。等待期间没有选择时按默认确认处理；已经给出本地推荐时按跳过处理，不会自动播放。AI 命令需要在 `ai` 中填写 API Key；未配置时会直接提示 AI 未启用。

BV 号点歌使用好友私聊的 `@点歌 BV号` 或 `@B站点歌 BV号`。识别时会修复常见 OCR 错字，数字 `1` 保持原样；单独发送 BV 号或 `@BV号` 不会触发点歌。

大厅倒计时会保存，重启后扣除程序关闭期间经过的时间继续计时。计时结束且未确认进入新大厅时，会暂停播放并停止歌词，保留当前曲目、进度和队列；关闭期间已到期的歌曲在重启后保持暂停。进入新大厅会清除旧计时，重新检测大厅时更新剩余时间。按现有 OCR 规则，识别到的剩余时间会预留一分钟。

### AI 曲库搜索与二次搜索

使用 `@AI点歌` 或 `@AI搜索` 时，会同时查找已记录的曲库和在线平台，再由 AI 从搜索结果中选歌。普通点歌以在线搜索为主，并用匹配度比较已有的曲库记录；普通搜索只使用在线搜索。大厅里被映射为好友、管理员或主人的成员，在线搜索范围与好友私聊一致，`@AI点歌` 同样会搜索包括 B 站在内的全部音源。曲库按歌名、歌手匹配关键词，最多提供 10 个候选，歌名和歌手连写或调换顺序也能命中；昵称、拼音或口语表达可由后续 AI 二次搜索处理。

在线结果不够理想而本地曲库有更合适的记录时，机器人会在同一批消息里追加一条本地推荐，并给出 `@本地`。本地兜底跨所有音乐源查找，因此指定的音乐源没有记录时，也能推荐其它来源的曲库记录。本地只有一首时，回复 `@本地` 会直接选用；有多首时会单独发送一条本地候选列表，按 `@1`～`@5` 选择。没有本地推荐时 `@本地` 会被忽略，不会中断当前点歌。本地推荐只在本地匹配优于在线结果时出现，等待超时按跳过处理，不会自动播放；该行为默认开启，可在 `ai` 中关闭。

标有“曲库”的歌曲来自本地记录，播放时仍需满足平台的账号和版权要求。同一平台的同一首歌会合并显示，在线平台确认无法播放的歌曲会被排除。缓存关闭、曲库为空或曲库查询失败时，继续在线搜索；在线搜索失败或没有结果时，可从已有曲库候选中选歌。大厅、好友私聊和指定音乐源的使用范围保持一致，唯一的区别是 B 站来源只对好友及以上开放：好友私聊可用，大厅里未映射的成员不可用，被映射为好友、管理员或主人的成员可用。本地兜底同样遵守这条限制。

AI 会先搜索原始文字，再判断是否需要把别名、译名、简称、拼音、谐音、OCR 错字或口语表达改成更适合搜索的歌名、歌手。有把握时会提示“AI理解搜索词”并再搜索一次；每次点歌最多搜索两轮，第二轮仍使用原来的音乐源范围和伴奏偏好。

第二轮结果会优先供 AI 选择，最终仍按原始点歌要求选歌。AI 无法判断、分析出错或二次搜索失败时，保留首轮可用结果；首轮歌曲全部受账号或版权限制时，不会靠改写搜索词继续尝试。任一轮确认无法播放的歌曲都会保持排除。等待时间可能比普通点歌更长，之后仍可按提示使用 `@确认`、`@跳过`、`@选择`，并遵守歌曲审核、重复点歌和排队规则。

### 歌曲审核与 AI 配置

在配置中心 `ai` 段填写服务地址、密钥、模型和代理。`ai`、`song_review` 和 `turtle_soup` 段可调整对应提示词；留空时使用内置默认提示词。

启用 `song_review` 后，游戏内点歌会在播放前检查歌曲是否符合房间设置。审核等级越高，表示歌曲越吵闹或越容易打扰；超过 `max_allowed_level` 的候选会被拒绝。控制台人工播放和队列操作不受歌曲审核限制。

### 个人歌单

发送 `@收藏` 收藏当前曲目，`@歌单` 在当前大厅进入独占选曲窗口，按 `@1`～`@5` 选择、`@换一批` 重抽、`@关闭` 退出。初次推荐和每次重抽发送新候选后，均有完整 20 秒供选择。未展示的曲目不足五首时全部展示；候选耗尽后再次重抽重新开始一轮。完整命令与例子见[个人歌单](playlist.md)。

## 5. 队列和歌词

| 命令 | 作用 |
| --- | --- |
| `@队列`、`@列表` | 分批发送完整点歌队列，不压缩歌曲信息 |
| `@队列删除 1` | 删除第 1 首队列歌曲，也可以写多个编号 |
| `@队列清空` | 清空待播放队列 |
| `@歌词` | 查询当前歌词 |
| `@歌词 秒数`（例如 `@歌词 10`） | 按后台歌词逻辑在指定秒数内自动发送变化的歌词，最长 300 秒；正式命令执行时暂缓发送 |
| `@持续歌词` | 主线持续发送歌词；正式命令到来时结束 |
| `@后台歌词` | 后台监听歌词，正式命令执行时暂缓发送，完成后继续 |
| `@单曲歌词` | 后台持续发送当前歌曲歌词，切歌后自动停止 |
| `@停止歌词` | 停止后台歌词 |

歌词显示偏晚时，可在配置中心把 `timing.playback.lyrics_lead_seconds` 设为需要提前的秒数。该值支持小数，范围为 `0` 到 `60`，保存后立即生效；`0` 表示保持歌词原始时间。

队列和播放状态会自动保存。程序会尽量避免短时间内重复播放同一首歌；需要人工指定播放内容时可使用 Web 面板。

## 6. 聊天值守模式

默认使用一级值守。好友私聊可使用以下命令：

| 命令 | 作用 |
| --- | --- |
| `@值守模式 一级` | 切换到一级值守 |
| `@值守模式 二级` | 切换到二级值守 |
| `@值守模式 状态` | 查看当前模式 |

一级值守直接观察游戏聊天框。二级值守观察当前大厅气泡和好友未读消息，适合需要持续停留在千星二级界面的场景。切换失败时程序会尝试恢复到可用的监听界面；普通命令会在当前值守模式下继续处理。

一级值守在确认进入游戏、进入千星或邀请进入新大厅后，会跳过首次出现的聊天消息，避免重复执行旧命令。如果最初画面没有聊天消息，会继续等待首批消息出现；之后的新消息正常处理。普通菜单返回和短暂未知状态不触发此规则。

## 7. 好友操作和管理

好友私聊支持：

| 命令 | 作用 |
| --- | --- |
| `@邀请1`、`@邀请654321` | 邀请好友进入大厅；数字可作为序号或大厅密码。最近 5 个已执行序号会去重，第 6 个新序号出现后最早的序号可再次使用 |
| `@麦克风` | 切换麦克风 |
| `@W/@S/@A/@D [秒数]` | 移动角色，默认 1 秒 |
| `@C` | 按一次 Ctrl |
| `@CW/@CS/@CA/@CD [秒数]` | 组合 Ctrl、中键和方向键 |
| `@F`、`@X` | 在一级界面发送一次对应按键 |
| `@通告 内容` | 向当前大厅发送内容 |
| `@拉黑UID123456789` | 管理员/主人直接拉黑；其他身份沿用投票流程 |
| `@屏蔽UID123456789` | 发起 UID 屏蔽聊天投票 |

邀请确认在大厅发送 `@邀请确认`、`@同意邀请`、`@邀请拒绝` 或 `@拒绝邀请`。普通身份的投票操作及屏蔽聊天操作继续使用配置的同意人数和等待时间。

### 管理员拉黑

在配置中心的身份映射中，为游戏内昵称设置管理员或主人身份后，可用 `@拉黑UID123456789` 直接拉黑，无需投票。UID 须为 9 位半角数字。其他身份仍需投票，`@屏蔽UID123456789` 也继续使用原有投票规则。

管理员直接拉黑时，会接管同一 UID 尚未结束的投票，取消该投票已经排队的结果，避免重复执行。正式操作前会再次核实权限；权限已撤销或找不到身份绑定时会取消。消息颜色和显示备注不会赋予管理权限。目标定位或执行确认失败时，请查看操作结果；结果未知时程序不会自动重试。

### 邀请后的就绪提示

邀请进入新大厅后，程序先确认已经留在大厅，并等待一级界面连续稳定 2 秒；随后打开聊天，确认进入二级界面，再发送就绪提示。

界面未知、无法观察画面、等待超时或任务取消时，不会发送提示。发送失败会记录在邀请结果中，播放队列保持原样。

以下命令用于管理识别状态，不会显示在普通帮助中：

| 命令 | 作用 |
| --- | --- |
| `@启用`、`@禁用` | 启用或禁用识别 |
| `@闲置退出`、`@闲置退出 20` | 管理闲置退出；带数字时设置等待分钟数 |

`@闲置退出` 的时间单位为分钟，最小为 15 分钟；触发后会暂停播放器并关闭目标游戏窗口，程序本身继续运行。

## 8. 娱乐玩法

- 成语接龙：发送 `#接龙` 或 `#同音接龙` 随机开局，也可紧接命令指定成语；详细规则见[成语接龙](idiom-chain.md)。
- 斗地主：发送 `#斗地主` 创建三人房间，详细规则见[斗地主与跑得快](card-games.md)。
- 跑得快：发送 `#跑得快` 创建三人房间，详细规则见[斗地主与跑得快](card-games.md)。
- 海龟汤：发送 `#海龟汤` 开始，详细规则见[海龟汤](turtle-soup.md)。
- 谁是卧底：发送 `#卧底` 或 `#卧底双` 创建报名房间，详细规则见[谁是卧底](undercover.md)。
- 塔罗：`#塔罗牌` 查看当天三张牌，命令带问题自动调用 AI，不带问题只给基础牌义。`#塔罗牌帮助` 查看全部命令。不占用其他娱乐会话，不暂停音乐或改变播放队列。

### 塔罗抽牌与 AI 解读

| 命令 | 作用 |
| --- | --- |
| `#塔罗牌 [问题]` | 查看当天三张牌：现状、提醒、建议；带问题时自动请求 AI 解读 |
| `#塔罗牌重抽 [问题]` | 提前更换当天的三张牌，新牌可能与之前相同 |
| `#塔罗牌AI [问题]` | 解读当前三张牌，不重新抽牌 |
| `#塔罗牌帮助` | 查看命令和规则 |

回复先给出标题，再逐条列出三张牌：

```text
用户的今日塔罗牌
现状：愚者·正位，保持好奇，先从小步尝试开始。
提醒：圣杯三·逆位，检查配合方式与分工。
建议：宝剑八·正位，持续练习，专注眼前一步。
```

塔罗使用 78 张牌，每张都有正位和逆位牌义。三张牌从同一组中抽取，互不重复；正逆位按每张独立随机，可能出现三张都为正位或都为逆位。

同一游戏内昵称每天使用同一组牌，按 UTC+8 日期在每天 00:00 后首次使用时更新。同一天重复查看或重启程序，牌组都保持不变。

问题可选，最多 80 字。命令带问题时会自动请求 AI 解读，不带问题只显示牌面和基础牌义；也可以用 `#塔罗牌AI` 主动请求解读。AI 使用现有的服务商、模型、密钥、代理和超时配置，解读提示词为程序内置；未启用或解读失败时，仍保留基础牌义，不会自动换牌。

重抽和 AI 解读共用每人 30 秒冷却，普通查看不占用冷却。解读会分成短消息发送。

斗地主和跑得快由配置中心 `landlord.enabled` 控制，默认开启；其他玩法按各自配置段控制。首次使用海龟汤或谁是卧底前，还需要按对应示例准备题库或词库，并在对应配置段中填写文件路径。

## 9. 配置中常用项目

通过 Web 面板「配置中心」查看与修改功能配置（见 [Web 面板使用](web-tools.md)）。`config.yaml` 用于存储位置、Web 监听和日志等启动配置。以下字段名与配置中心页面一致：

通常只需要修改以下配置：

| 配置段 | 用途 |
| --- | --- |
| `window` | 游戏进程名和画面尺寸 |
| `playback` | 原生播放凭据目录、登录辅助器路径和登录超时 |
| `http` | Web 面板监听地址、端口和访问令牌 |
| `ocr.backend_priority` | OCR 后端顺序；默认 `openvino`、`cpu`（OpenVINO 优先，失败自动回退 MNN CPU），通常无需修改 |
| `ai` | AI 点歌的地址、密钥、模型和代理 |
| `song_review` | 歌曲审核开关和审核阈值 |
| `idiom_chain` | 成语接龙开关和超时 |
| `landlord` | 斗地主/跑得快开关、组局和出牌超时、托管阈值 |
| `turtle_soup` | 海龟汤开关、题库和 AI 参数 |
| `undercover` | 谁是卧底开关、词库和人数限制 |
| `custom_workflows` | 自定义命令流程 |
| `kugou` | 酷狗设备信息（GUID、设备型号、设备 MAC） |

OCR 后端默认顺序为 `openvino`、`cpu`：发布包已内置 OpenVINO 运行时（`deps/openvino/`）和 PP-OCRv6 的 IR 模型（`deps/models/` 下的 `.xml` 与 `.bin`），通常不需要改动。OpenVINO 初始化失败时（例如很旧的 CPU 或运行时文件缺失）会自动回退到 MNN CPU，并在日志中提示。首次启动会预热聊天 OCR 的固定形状并写入 `deps/data/openvino-cache`，因此第一次识别稍慢，之后复用编译缓存。如果希望强制使用 MNN CPU，把 `ocr.backend_priority` 改为只保留 `cpu`，并保留 `ocr.det_model`、`ocr.rec_model` 和字符集路径即可。`ocr.openvino.device` 默认 `CPU`；随包运行时来自官方 Windows x64 分发包，默认只用 CPU。GPU/NPU 需要对应硬件与驱动，项目只验证了 CPU 路径，修改 `device` 后需自行确认日志和识别结果。

酷狗的登录与取流请求使用设备信息。请在配置中心 `kugou` 段填写设备 GUID、设备型号和设备 MAC 三项，三项需同时填写，保存后在下一次酷狗登录时生效；程序不会自动生成设备信息，三项留空时沿用凭据目录下已有的 `kugou-device.json`。缺失设备信息时，酷狗登录会提示先补全该项配置。

取值参考:设备 GUID 填该设备的设备号,推荐 UUID v4 形式(程序会按酷狗的方式换算成设备 mid),也可以直接填已规范化的 32 位设备号;设备型号填设备上报的型号名,任意稳定字符串即可(例如 `KuGouMusicApi`);设备 MAC 填该设备的 MAC 地址(形如 `AA:BB:CC:DD:EE:FF`)。三者用于设备注册与登录续期,同一套值长期固定使用即可;更换设备号只影响该账号的登录续期,不需要重新配置音乐源。

酷狗账号的「领取VIP」和「升级VIP」只在 Web 面板「账号登录」中手动点击时执行，程序不会自动领取或定时领取；频繁点击会提高账号被上游限制的概率。酷狗要求人机验证时，相关请求会暂停一段时间并在结果中提示，稍后重试即可。

在 `identity.mappings` 中，「游戏内昵称」填写游戏中识别到的昵称，「显示昵称」填写希望对外显示的名称。填写后，游戏回复和 Web 面板会使用显示昵称；留空时使用游戏内昵称。好友定位和权限判断仍使用游戏内昵称。

远程访问 Web 面板时，把 `http.host` 改为需要的监听地址，并设置非空 `http.access_token`（`http` 属于启动引导段，仍需在 `config.yaml` 中修改，配置中心只读展示）。本机访问建议保持默认的 `127.0.0.1`。

## 10. 自定义命令

在配置中心 `custom_workflows` 段开启自定义命令，设置流程名称、触发命令、使用场景和操作步骤。可按需要配置模板匹配、坐标点击、按键和发送消息。

例如，把触发命令设为“测试流程”、使用场景设为好友私聊、操作设为按下 F，保存后在好友私聊发送 `@测试流程` 即可执行。

内置命令和确认、投票命令优先。每个流程按设置顺序执行，某一步失败时停止后续步骤。

## 11. Web 面板

打开 `http://127.0.0.1:18888/` 可以查看：

- 游戏窗口、值守模式、播放器和队列状态。
- 日志、最近识别到的聊天和待处理任务。
- 远程点歌、播放控制、队列管理、歌词和启动游戏。
- 海龟汤、谁是卧底和自定义流程的可用控制。

在「账号登录」中启动登录时，登录辅助器会打开对应平台的官方登录页。登录完成后，账号状态会回到当前页面；二维码只在当前登录会话有效。具体步骤见 [平台登录](login-qr-feasibility.md)。

在播放页的「点歌榜」选择最近 7 天、最近 24 小时、最近 30 天或全部，再点击「刷新」查看成功播放的点歌次数；统计规则见 [Web 面板使用](web-tools.md#6-点歌榜)。

`/tools` 高级页可以查看截图、测试 OCR、匹配已配置模板和发送按键。工具失败会在结果中提示原因，正式聊天命令继续处理。

## 12. 快捷键与常见问题

- `F7`：暂停或恢复聊天扫描。
- `F12`：退出程序。

### 常见问题

**没有识别到命令**

检查游戏是否处于一级或二级值守对应的界面、聊天标识颜色是否正确，以及 `screen` 坐标是否与当前画面分辨率一致。

程序会记住最近执行的命令，避免回复、切换面板或 OCR 抖动让同一条命令重复执行。同一条文本重新发送后，如果仍落在原位置附近，也可能被视为已经处理；请等原消息滚出可见聊天区域、完成两轮非空 OCR 扫描后再重试。首屏历史抑制仅限粉色好友命令，以消息颜色判断，与用户权限无关；蓝色大厅首屏可正常执行，已经成功处理的命令仍受成功锁保护。处理好友未读只提升所选最新消息，不执行整屏粉色历史。

**OCR 首次启动变慢或日志提示回退**

默认使用 OpenVINO。首次启动会预热固定识别形状并写入 `deps/data/openvino-cache`，第一次识别可能稍慢；该目录可以删除后重建。日志出现“OCR 后端初始化失败，尝试下一个”说明 OpenVINO 未能启用，程序已自动回退 MNN CPU；如需固定使用 CPU 后端，按上一节把 `ocr.backend_priority` 改为 `cpu`。

**无法播放歌曲**

检查 `playback.credential_directory`、登录辅助器路径和 FFmpeg DLL 是否存在，并先用 `@状态` 或 Web 面板确认原生播放运行时状态。

**AI 命令提示未启用**

检查对应配置段的 `api_key`、`endpoint` 和 `model`，在配置中心保存并按页面提示等待配置生效。

**Web 页面无法访问**

确认程序已启动、端口没有被占用。页面能打开但数据读取或操作失败时，检查页面填写的访问令牌是否与 `config.yaml` 中的 `http.access_token` 一致；本机访问也需要令牌。

**游戏关闭后仍显示旧截图**

重新启动游戏窗口并等待下一次有效扫描；目标窗口关闭后，旧画面不会继续作为新的识别结果使用。

**消息延迟、备注名丢失或身份识别不准**

先确认当前是否在使用外部聊天源。若配置中心「外部聊天源」的 `enabled` 为开启，检查 ChatBridge 进程是否在运行、Web 面板总览里外部源是否显示已连接；连接断开时程序会按 `lease_timeout_ms` 回落到 OCR，此时消息有延迟、拿不到备注名、身份只能按名字推断，属于预期行为。若 `enabled` 为关闭，上述现象是纯 OCR 链路的正常限制，可考虑启用外部聊天源（含风险，见下一节）。

## 13. 外部聊天源（ChatBridge）

外部聊天源是可选的第三方消息通路。开启它之后，程序不再用 OCR 识别聊天内容，改由 `Miliastra-Wonderland-ChatBridge` 通过本地 WebSocket 推送消息；界面识别（一级/二级/未聊天）仍由模板匹配完成。

`Miliastra-Wonderland-ChatBridge` 是**独立的第三方可执行文件**，不是本项目的一部分。本程序只在需要时替用户启动它，不修改它，也不控制它。

### 开启前需要知道的事

ChatBridge 的工作方式是：**拉起游戏 → 向游戏进程注入 DLL → 嗅探聊天包 → 通过本地 HTTP/WebSocket 提供消息**。

**向游戏进程注入 DLL 可能违反游戏的用户协议**，存在被判定为第三方工具、进而导致账号处罚的可能。该风险由使用者自行判断与承担，本项目不做任何保证。

### 开启步骤

1. 取得 `miliastra-wonderland-chatbridge.exe`。它不由本项目提供，需自行获取。
2. 打开 Web 面板「配置中心」，进入「外部聊天源」段。
3. 填写 `executable`（可留空，程序会按约定目录查找），确认 `url` 与 `token`。
4. 把 `enabled` 设为开启，保存配置。该段字段为「空闲重载」，保存后需等待当前任务结束才会生效。
5. 若希望程序自动启动 ChatBridge，再开启 `auto_start`，并填写 `self_uid`（见下）。

### 字段含义与填错后果

| 字段 | 含义 | 填错的后果 |
| --- | --- | --- |
| `enabled` | 是否启用外部聊天源 | 关闭时完全走 OCR，聊天仍可用，只是有延迟、拿不到备注名 |
| `url` | ChatBridge 的推送地址，默认 `ws://127.0.0.1:18889/stream`（端口 = `http.port` + 1） | 地址错误会导致连不上，程序按 `lease_timeout_ms` 回落到 OCR |
| `token` | 鉴权令牌，通常与 `http.access_token` 相同 | 留空或与服务端不一致时连接会被拒绝 |
| `reconnect_ms` | 断线后的重连间隔 | 调得过大时断线后恢复变慢 |
| `lease_timeout_ms` | 多久没有消息就回落到 OCR | 调得过大时 ChatBridge 已挂但程序仍以为在用外部源；调得过小时消息稀疏场景会频繁误判失联 |
| `auto_start` | 发现 ChatBridge 没在监听时替你启动它 | 开启时**要求游戏未运行**，否则 ChatBridge 会因游戏已在运行而退出；启动失败后本程序退避 30 秒再重试 |
| `executable` | `miliastra-wonderland-chatbridge.exe` 的完整路径 | 留空时依次查找程序目录及其上一级的 `deps/bin`、`Miliastra-Wonderland-ChatBridge` 目录、以及解压出的带版本号发布目录；都找不到会提示路径配置 |
| `self_uid` | 本机游戏账号的 UID | 两个后果：**填错会把 BOT 自己的发言当成命令再执行一次**；**留 0 或填错会让私聊对端被认成 BOT 自己**，个人歌单与记忆归属静默失效（见下） |

#### 关于 `self_uid`

`self_uid` 有两个用途，填错各有一个后果。

**用途一：区分「本机账号自己的发言」与「其他玩家的发言」。**

**填错时，BOT 自己发出的回复会被当作玩家的新命令读回来，再次执行一次**，可能出现重复点歌、重复回复等异常。

**用途二：排除私聊的对端。**

`self_uid` 也用于排除私聊的对端：**留 0 或填错时，玩家私聊 BOT 会被识别成 BOT 与自己对话**，按身份归属的功能（个人歌单、记忆归属）会失效，**且不会产生任何错误提示**。

第二条后果比第一条更不易察觉：功能静默失效，日志里没有报错，只能从「私聊里点歌不进自己的歌单」这类现象反推。**使用外部聊天源时建议始终填写 `self_uid`。**

以上是**本程序传参或配置错误**导致的后果，不是 ChatBridge 的缺陷。

- 仅「自动启动」时由本程序把 `self_uid` 作为 `--self-uid` 传给 ChatBridge。
- 自行部署并手动启动 ChatBridge 时，请在你的启动命令里填 `--self-uid`，配置中心的 `self_uid` 可留 0。

### 已知风险

1. **注入类工具的账号风险。** 向游戏进程注入 DLL 属于修改游戏运行时的行为，可能违反游戏的用户协议，存在账号处罚风险。风险大小取决于游戏运营方如何判定。
2. **「自动启动」会替你启动该注入器。** 关闭 `auto_start` 后，本程序不会主动启动任何外部程序。
3. **访问令牌以命令行参数明文传递。** 本程序通过 `--token` 把令牌作为命令行参数传给 ChatBridge，同一台机器上的其他程序与用户可以在进程列表中看到该令牌。多账号或多用户共用一台机器时尤其需要注意。
4. **不要把 `url` 与 `token` 指向不受信任的目标。** 一旦配错，聊天内容（含玩家昵称、UID、正文）会发往该地址。默认地址为本机回环，请勿改成本机以外。

### 关闭与回落

把 `enabled` 设为关闭并保存即可回到纯 OCR 链路，功能不受阻。

外部源在运行中失联（进程退出、网络中断）时，程序在超过 `lease_timeout_ms` 后自动回落到 OCR，并在恢复后重新接管。无需手动切换。

配置方法与风险摘要也见 [README · 外部聊天源（可选）](../README.md#外部聊天源可选)。
