## 1. 三条不变量

整个状态机建立在三条硬规矩上，**所有判据和文档都必须服从**：

1. **判不出来就返回 `unknown`，绝不猜。**
   `unknown` 是一个诚实信号，不是"其它"。往它里面塞东西会让它失去意义。
2. **阈值只能取"已测出不重叠区间的中点"。**
   不许为了已观测的结果去调阈值。每条判据都必须能说出"正样本区间"和"负样本区间"，
   以及切点是怎么算出来的。
3. **没实测过的能力不许写成已支持。**
   文档里每个"✅"都必须能指到一张帧、一条日志或一条命令。

| 5 | 提瓦特大世界 | `overworld` | 祈愿图标模板，**只在连续 2 帧 `unknown` 之后的回退里** | ⚠️ **不可靠** | criteria §5 |
| 6 | 登录/点击进入 | `game_gate` | OCR 找「点击进入」（区域 `(900,1000) 130x40`） | ✅ 实机验证（离线不可验） | criteria §0 |

**判定优先级**（自上而下，先命中先返回）：

```
loading（最优先，整屏极端色调，不可能与别的状态冲突）
  → friend
  → secondary-back
  → 若返回按钮命中：return-to-teyvat（主菜单）
  → 聊天标记（含底栏近白否决）
  → 回退闸门：world_wish（仅在连续 2 帧 unknown 之后）
```

## 4. 接口

| 接口 | 方法 | 用途 |
|---|---|---|
| `/debug/ui-state` | GET | 查当前状态；加 `?image=路径` 可离线判定已保存帧 |
| `/debug/command` | POST | 原子输入：`press_key` / `click` / `activate` |
| `/debug/screenshot` | GET | 抓当前帧 |
| `/debug/mode?mode=enabled\|disabled` | POST | **真正的输入门**（`gameInputAllowed` 只是派生报告值） |
| `/debug/events` | GET | 状态事件流（含 `run.started/finished`） |

**断言面**：沙盒的 `SandboxAssertion` 可以直接断言 `ui_state` 的期望类型，
所以状态机是**可断言**的，不只是可查询。

**一键工具**：

```powershell
pwsh -File docs/ui-state-evidence/classify-frame.ps1 -Image <图片>   # 任意截图 → 状态（判不出就 Unknown）
pwsh -File docs/ui-state-evidence/game-log-transitions.ps1           # 从游戏日志提取加载/世界切换时间线
cargo test --lib loading                                             # 加载界面判据（含分离度自证）
```

## 7. 方法论纪律（都是踩过的坑换来的）

1. **点击坐标必须放大后画网格量。**
   凭整屏预览估坐标，本项目错了 4 次（偏 59 / 32 / 23 像素，全部落空）；
   放大 3~6 倍画 20 像素网格量出来的坐标，一次就中。
2. **每次输入前必须先 `activate`。**
   不给游戏窗口激活就发按键，应用照样返回 `ok:true`，但游戏**毫无反应**——
   第 56 节因此误判「Escape 打不开奇域主菜单」，白查了一轮。**先激活，再发键。**
3. **面板操作之后要留动画时间。**
   关掉面板立刻按 `M` 会被吞掉，等 2 秒再按才行。
3. **正样本集必须查全，再做分离度。**
   第 47 节的判据看着分离度 0.3944 很漂亮，实际漏掉了真实大厅帧 `overworld-hub.png`。
4. **切点只取区间中点。**
   已测出正样本下界与负样本上界，切点 = 两者中点。**不许为已观测结果回头调阈值。**
5. **静态画面会让连拍帧逐帧完全一致。**
   不能只看"帧有没有变"判断游戏有没有动，必须同时看状态和游戏日志。
6. **游戏日志是独立证据源。**
   `%USERPROFILE%\AppData\LocalLow\miHoYo\原神\output_log.txt` 里有
   `OnBeginLoadScene` / `FinishLoadSceneAynsc` / `ChangeGameWorld`，
   可给截图打时间戳，且不依赖应用。
7. **模板匹配的边界：应用用的是灰度 1:1 SAD，容不下缩放。**
   凡是会缩放的 UI（大厅底栏）都不能靠它当判据。
8. **找锚点要用多帧叠加，而且必须换视角再拍。**
   停着不动连拍，画面几乎不变，分不出"UI 不动"还是"世界不动"。
   正确做法：**先用 `key_down`/`key_up` 长按走动（点按不动），再用 `drag` 拖动鼠标转视角**，
   拍到 6~7 张**视角差别很大**的帧（相邻帧平均像素差应 > 10），再逐像素算方差。
9. **⚠️ 屏幕边缘的 HUD 大部分是"会动"的，不能当锚点。**
   2026-10-03 用 7 张换过视角的提瓦特帧实测（灰度 8 像素取样，平均标准差）：

   | 区域 | 平均标准差 | 能否当锚点 |
   |---|---|---|
   | 中下 血条 `(700,985) 520x45` | **10.78** | ★ 最稳 |
   | 左下 聊天栏 `(0,980) 420x100` | **11.39** | ★ 最稳 |
   | （对照）画面正中 `(760,400) 400x300` | 18.68 | 世界，本来就该变 |
   | **右上 图标行** `(1250,0) 670x95` | **20.23** | ✗ 随进度增减 |
   | **左上 小地图** `(70,55) 320x320` | **20.33** | ✗ 实时更新 |
   | 左缘 图标条 | 23.19 | ✗ |
   | 右下 UID/技能 | 27.84 | ✗ |
   | **右缘 技能条** `(1770,470) 150x430` | **34.44** | ✗ 冷却动画 |

   ⇒ **右上角按钮行、小地图、右侧技能条的"不稳定性"甚至超过世界画面本身**，
   **位置绝对不是可靠的判据**。真正稳定的锚点在**屏幕下方的常驻底栏**（聊天栏 / 血条 / 大厅底栏）。
   证据：`ui-state-evidence/anchor-teyvat-56/stability-map.png`（黑=不变）。
   注：绝对标准差含 JPEG 压缩噪声，基线约 5~10；**看的是区域之间的相对排名**。

10. **首尾帧逐像素做差是最直接的复核方法，而且它和方差法吻合。**
    拿视角差别最大的**首帧与末帧**直接相减，不经过任何统计：

    | 判据 | 占比 |
    |---|---|
    | 差值 **= 0（逐像素完全相同）** | **2.51 %** |
    | 差值 ≤ 3 | 10.40 % |
    | 差值 ≤ 6 | 18.30 % |
    | 差值 ≤ 10 | 27.21 % |
    | 差值 ≤ 40 | 73.78 % |

    不变掩码（`ui-state-evidence/anchor-teyvat-56/invariant-mask.png`，白=完全相同）里
    **唯一"实心成片"的元素是屏幕中下方那一条血条**（原图 x 800-1120, y 910-930）；
    小地图只剩外框、右上图标行只有部分图标、右缘图标各有小块，
    **中间的世界区域整片是黑的**。

    **⇒ 两种互相独立的方法给出同一个答案**：方差法排名第一的「中下血条」(sd 10.78)
    与逐像素做差法里唯一实心的那个元素，**是同一个东西**。

11. **⚠️「最不变」≠「最有用」——锚点必须同时满足两个条件。**
    把底栏/边缘切成 40×40 的小块做**极差**（不是标准差，极差=0 才是逐像素完全一致），
    1754 块里**只有 1 块**极差 < 3：

    | 位置 | 极差 | 是什么 |
    |---|---|---|
    | **`(40,40)` 40x40** | **1.01** | **左上角的派蒙头像图标** |
    | `(40,20)` | 6.49 | 派蒙图标上部 |
    | `(40,740)` | 11.95 | 左缘 |
    | `(100,1020)` | 13.36 | 左下聊天 Enter 按钮 |

    **但派蒙图标恰恰是最没用的锚点**：它是**全局常驻 HUD**，每个界面都有
    （项目里 `paimon-menu` 模板在 66 帧语料里命中 **26 帧**）。
    同理 **UID 文本**、**血条**也都是全局常驻的；而且**血条是半透明的**，
    背景世界会透出来，会被世界污染（证据 `anchor-teyvat-56/cmp-topleft-paimon.png`）。

    ⇒ **判据配方（两个条件缺一不可）**：

    | | 条件 | 怎么筛 |
    |---|---|---|
    | **(a)** | 在**同一界面**的不同视角下**不变** | 换视角连拍 + 逐像素做差 |
    | **(b)** | 在**其它界面**上**不存在或明显不同** | 拿正负样本语料互测 |

    只满足 (a) 的元素（派蒙图标 / UID / 血条）**不能用来区分界面**。

    **§48 的底栏近白占比之所以有效，正是因为它同时满足了两条**：
    千星底栏有多个白色按键（`💬 Enter | 👥 O | 🔊 Alt+N | 🎤 N`）
    而提瓦特只有一个 `Enter` —— 同界面内稳定、跨界面有差异。

12. **⭐ 结论：点锚点在千星/大世界里根本不存在，判据只能用「统计量」。**
    2026-10-03 在**千星大厅**用同一套方法复验
    （`key_down`/`key_up` 长按 **WASD** 走动换视角，9 帧，相邻帧平均差 7.6~43.8）：

    | 指标 | 千星大厅 | 提瓦特（对照） |
    |---|---|---|
    | 首尾**逐像素完全相同** | **1.41 %** | 2.51 % |
    | 差值 ≤ 6 | 12.04 % | 18.30 % |
    | **极差 < 3 的 40x40 块** | **1 / 5035** | 1 / 1754 |
    | 那个唯一的块 | **`(40,40)` 极差 0.54** | **`(40,40)` 极差 1.01** |

    ⇒ **两个界面里唯一真正不变的东西是同一个：左上角的派蒙头像。**
    它是**全局 HUD**，处处都在 ⇒ **判别力为零**。

    **⚠️ 追加更正（用户提示后实测）**：曾以为「派蒙头像在两个世界略有不同」。
    分离度实测（组内差 vs 组间差，不重叠才算可分离）：

    | 区域 | 组内最大 | 组间最小 | 分离 | 结论 |
    |---|---|---|---|---|
    | **派蒙脸本身** `(22,16) 56x62` | 24.28 | **11.82** | **-12.46** | ✗ **两个世界完全相同**（组间甚至比组内还小） |
    | **它背后的小地图** `(86,30) 66x120` | 19.64 | **66.64** | **+47.01** | ★ **完全不重叠** |

    ⇒ **差异不在派蒙脸，在小地图**（提瓦特是绿黄地形、千星是紫蓝螺旋）。
    **但不能据此立判据**：提瓦特小地图的颜色**随地区变**（雪山白、沙漠黄），
    只有千星一侧是固定的紫蓝。要立判据必须补更多提瓦特地区的样本，**本轮不立**。
    截图证据：`dist/sandbox-run/cmp-paimon-worlds.png`（左提瓦特、右千星）。
    其余所有 UI（底栏、图标行、小地图、技能条）极差都在 8~14，
    因为**它们都是半透明的，背景世界会透出来**。

    **⇒ 所以判据只能是「统计量」，不能是「点锚点」。**
    这正好解释了本项目此前的全部失败：
    `wonderland-map-star`(37/66)、`paimon-menu`(26/66)、`world-wish`(40/66)
    这些模板之所以没有判别力，就是因为它们要么匹配到全局 HUD，要么匹配到半透明区域；
    而 §48 改用**区域近白像素占比**（一个统计量）一次就成了。
    证据：`ui-state-evidence/anchor-hall-56/invariant-mask.png`（白=完全相同）。

    **⇒ 附带确认：`drag` 转不动视角。**
    在千星大厅连做 8 次 `drag(960,540 -> 1200,540)`，相邻帧平均差只有 **3.6~4.4**
    （即几乎没动，只有 NPC 挪了位置）；改用长按 **WASD** 后立刻升到 **7.6~43.8**。
    另外 `parse_key`（`src/adapters/windows/input.rs:231`）**不支持方向键**，
    只认 `enter/escape/control/F1~F12` 和**任意单个字符** ⇒ 方向键发不出去，只能用 WASD。
