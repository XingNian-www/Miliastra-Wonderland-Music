### 8.1 同时暴露的不稳定现象（**未解决**）

`secondary` 在两次稳定确认之间反复回落到 `transition:unknown`（seq 19、21）。
两种解释目前**无法从证据区分**：

1. 用户确实在来回切换，`unknown` 是切换过程中的正常过渡；
2. 二级界面判定本身在抖动（间歇性失败）。

在区分清楚之前，**不得声称"二级状态稳定"**。
区分方法：让二级界面静止不动，观察是否仍出现 `unknown` 回落。

### 8.2 抖动机制：多为"标签重稳"，但有一个反例

2026-10-03 做过一次 **110 秒空闲观测**（用户未操作），只收到 2 条迁移：

| seq | label |
|---|---|
| 25 | `transition:unknown` |
| 26 | `primary:friend` |

对比上一轮同一位置的 `primary:marker blue=0 yellow=5 pink=0`：**标签从 marker 变成了 friend**
（`"好友按钮"` 模板这次命中了）。这说明一个重要事实：

> `transition:unknown` 有很大一部分**不是分类失败**，而是**标签变化后的去重重稳**——
> `TrackedUiState` 要求连续 N 帧一致才算稳定，期间 `stable_kind()` 返回 None，
> 于是迁移事件里就出现了一次 `unknown`。**这是设计使然，属于正常过渡。**

**但有一个无法这样解释的反例**：第 8 节里 seq 19、21 是
`secondary:chat → unknown → secondary:chat`，**标签完全相同却又断开重连**。
标签没变就不该重稳，因此这不是"正常的标签变化过渡"。

**结论（未解决，不得声称稳定）**：
- 110 秒空闲窗口只有 1 次过渡 → 分类器**不是持续抖动**；
- 但 `secondary` 出现"同标签断开重连"，成因仍未确定；
- 在查清之前，**不得声明"二级状态稳定"**。

区分方法：让二级界面**静止不动**观察 2 分钟以上，看是否仍出现
`secondary → unknown → secondary`。若仍出现，即为判定抖动；若不出现，则上一轮是真实切换。

### 10.1 前缀形式（**容忍全角**）

`secondary_chat.rs:229-245` 显示，私聊里的命令行识别为：

`@
@<载荷>            → 前缀 '@'
#<载荷> / ＃<载荷>  → 前缀 '#'（**半角与全角 # 都接受**）
`@

然后统一规范化为 `<prefix>:<identity>` 作为命令身份。**全角 `＃` 也被接受**——
与本项目在聊天文本上"容忍全角/半角差异"的一贯做法一致。

### 10.2 对目标清单的更正：**"点歌面板"在应用侧不存在**

目标 (1) 列出的"点歌面板"，在应用这边**没有任何模板或界面判据**。
实际机制是**聊天命令** `@点歌 <歌名>`（`application.rs:1925` 直接断言了这一点）。

因此正确的表述是：**点歌不是面板，是聊天命令**。
如果游戏侧确实存在某个点歌 UI，那也**尚未被发现**，本文不臆测。

## 13. 已确认的缺陷边（**不得当作已支持**）

| 问题 | 影响 | 依据 |
|---|---|---|
| ESC → 主菜单被判成私聊 | 日常操作可达的误判 | 状态文档 §14.2、§17.2 |
| `game_gate` / `overworld` 从未稳定 | 这两个状态实际不可用 | 状态文档 §11（60MB 日志统计） |
| `world-wish` 抓的是「四角星圆环按钮」，真野外帧**不命中**、大厅页 0.9679 > 真帧 0.9643 | **判据方向是反的**，`overworld` 不可支持 | 状态文档 **§23**（离线 fallbackProbe + 视觉复核 verify-worldwish-mismatch.png） |
| `friend-blacklist` / `friend-block-chat` 区域不覆盖按钮 | 审核流程按钮定位在该界面失败 | 状态文档 §16 |
| 主世界判据 `world-wish` 在大厅得分更高 | 判据不充分 | 状态文档 §14.3 |
| 聊天 HUD 会**渐隐**（见 `step-3.png`） | 存在半透明中间态，可能是 `unknown` 抖动的来源 | 观察，**未量化** |

最后一行特别说明：`step-3.png` 捕捉到聊天 HUD **正在淡出**（半透明）。
这说明"聊天框开合"至少有 **显示 / 渐隐中 / 隐藏** 三种情形，
而分类器只看得到"有没有标记"。**该中间态尚未被测量，不得当作已支持。**

## 7. 实机观测到的迁移路径：大厅 → 提瓦特大世界（2026-10-03）

由应用自身的 `/debug/command` 直接驱动，每一步都留帧并记录应用推出的事件序号。

```
起点  奇域大厅                  kind=primary  primary:friend (stable, score 0.991)
  │   press_key Escape          —— 打开奇域主菜单（叠在大厅上的浮层）
  ▼
中间  奇域主菜单                kind=main_menu（规则 main_menu_template, score 1.0000）
  │   ↑ 同一帧上 secondary-back 也命中 0.9782（这就是误判源）
  │   click (1740,1017) 「返回提瓦特」
  ▼
确认  提示弹窗                  「是否离开当前大厅，返回提瓦特？」取消 / 确认
  │   click (1144,756) 「确认」
  ▼
过渡  kind=primary(marker) → unknown(transition)     应用事件 37 → 40
  ▼
终点  提瓦特大世界              kind=overworld (stable) 规则 world_wish_template —— 事件 41
```

证据帧：`docs/ui-state-evidence/transition-to-overworld/`（5 张）
加 `leave-hall-confirm.jpg`（确认弹窗）。

相关规则与坑见 `ui-state-machine.md` §44、§45。

> **先 activate 再发输入**。应用会拒绝向非前台窗口发送输入
> （报「当前前台窗口不是目标游戏进程，已中止输入」），
> 而 `ensure_foreground` 自己也要先过这个检查，单独调用会失败。
