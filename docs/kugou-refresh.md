# 酷狗登录续期：实测矩阵与结论

本文记录酷狗（Kugou）登录态「会丢失、账号不可用」的定位过程与实测证据。
目的是让后来的人明白：**续期返回 `20018` 是上游拒绝该凭据类型，不是我们拼错了
参数**，从而不必重复这套排查。

> 说明：下表矩阵中的 TLS 行为与错误码形状来自本分支的实测复现；其中
> 「空 token / 签名体错」两行由独立实现（已废弃分支 `kugou-login`）在同一批
> 调试中复现，结论一致。凡涉及**真实令牌**的行，均已脱敏，不含任何凭据。

## 核心结论（一句话）

**网页扫码登录得到的凭据天然不能做 Lite 设备绑定续期（恒 `20018`）；
能续期的只有概念版（lite）手机号登录下发的、带 `t1` 的凭据。**
所以「彻底不掉登录」的正解是走概念版验证码登录，而不是修 `login_by_token` 的参数。

## 实测矩阵

| # | 请求 | 结果 |
|---|---|---|
| 1 | `https://login.user.kugou.com/v5/login_by_token`（严格 TLS） | 握手失败：证书只覆盖 `*.kugou.com`，不匹配 `login.user.` 这个两级子域 |
| 2 | 同上，跳过证书校验 | 200 / `error_code=20018` |
| 3 | `gateway.kugou.com` + `x-router: login.user.kugou.com` | 200 / `20018`（与直连同一后端，`kg-svr-version` 一致） |
| 4 | `gateway.kugou.com` **不带** `x-router` | 502（说明路由头必需） |
| 5 | lite 参数 / 标准版参数 × 真令牌 / 假令牌 × 带 / 不带 Cookie | 全部 `20018` |
| 6 | 空 token，或把 `KugooPwd` 当 token | `20017`（请求形状错，**不是** `20018`） |
| 7 | Android 签名体算错 | `20006`（`err signature`） |
| 8 | 领 VIP `/youth/v1/ad/play_report`，真令牌 / 假令牌 | 均 `51002`（业务/设备侧拒绝，非鉴权问题） |
| 9 | 验证码登录 `/v7/login_by_verifycode`，假验证码 | `20020` + `data:"验证码过期"`（**证明签名与 RSA/AES 加密体全部正确**） |

### 矩阵怎么读

- **第 1 行**是根因一：那个主机名的证书从协议上就不可能通过严格校验。任何直连
  它的实现都会在传输层失败，且如果错误被日志降级吞掉，表现就是「续期静默无效」。
- **第 2/3/5 行**是根因二：把 TLS 问题绕开之后，上游仍然拒绝，说明问题不在传输层、
  也不在参数拼装。真实令牌、假令牌、lite/标准版、带不带 Cookie 结果一致 —— 这就是
  「凭据类型不支持」的典型特征。
- **第 6/7 行**是反向对照：如果那真是「我们拼错了」，应该落到 `20017` 或 `20006`。
  落到 `20018` 说明请求本身被正确理解，只是这个会话不被接受。
- **第 9 行**是正向证据：验证码登录链路在加密层面完全正确（否则会得 `20006`），
  只差一个真实有效的验证码。

## 由此确定的实现

1. **续期端点**改走 `gateway.kugou.com` + `x-router: login.user.kugou.com`
   （与上游 `module/login.js` 一致，全程 HTTPS，不跳过任何证书校验）。
2. **续期结果如实上报**：真换到新令牌才算成功；上游拒绝则返回
   `RefreshUnavailable`，把凭据标记为 `needs_reauth` 并**停止自动刷新调度**，
   而不是拿旧凭据冒充成功、再把下次检查顺延一整天。
3. **新登录走概念版验证码**（`/v7/send_mobile_code` + `/v7/login_by_verifycode`），
   这是唯一能在登录阶段就拿到 `t1` 的路径。缺 `t1` 时直接报错，不产出一份
   「登录即不可续期」的凭据。
4. **领取 VIP** 只做可读化与「先续期再重试一次」，不猜测参数去凑成功
   （`51002` 的成因仍需真机播放态才能进一步确认）。

## 仍然未知的部分

- **lite 凭据 + 真实 `t1` 能否过 `login_by_token`**：离线无法证实，需真机验证。
  在此之前不应宣称「掉登录已彻底解决」。
- **`51002` 的确切语义**：参数与上游逐字节一致、签名有效，仍被拒，说明是账号
  资格 / 活动开放状态 / 播放态之类的外部条件，未能归因。
