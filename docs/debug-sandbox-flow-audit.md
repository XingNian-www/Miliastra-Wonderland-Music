## 3. 发现

### F1（可用性/性能）搜索失败会空转满 5 秒

`timing.moderation.search_result_timeout_ms` 默认 **5000ms**。搜索不存在的 UID 时，"更多设置"模板永不出现，流程会轮询整整 5 秒才失败。

结合实测：每次轮询 ≈ 一次真机截图（主循环自身约 130ms）+ UI 状态分类（约 95–117ms），即约 240ms/次 → **约 20 次无效轮询、约 5 秒纯等待**，期间还与主循环争用同一个 UI worker。

**优化方向**：加入"未找到"的快速判定，而不是等满超时。

### F2（根因）游戏不提供"未找到"文本信号

实测确认：搜索不存在的 UID 后，界面只是**把输入框清空、按钮从"清除"变回"粘贴"**，不显示任何错误文案。

所以无法用 OCR 文本判定"未找到"。但存在**结构化信号**可判定：输入框回到占位文案 + `清除` 按钮恢复为 `粘贴`（即输入态被重置）。当前流程**没有检查这两个信号**，因此只能等超时。

**优化方向**：轮询时同时检查"输入态是否已被重置且更多设置模板仍不存在且已过最小等待"，据此提前失败，把 5 秒降到数百毫秒。

### F3（风险）ESC 是切换键，恢复逻辑依赖模板守卫

实测：一级界面按 ESC 会**打开**千星奇域菜单（我连续按两次 ESC 时复现）。

`recover_primary` 的安全依赖两个条件：`stable_kind == Primary` 直接返回；否则仅在 `stable_kind == Secondary` 或某个面板模板**连续稳定出现**时才按 ESC。逻辑上是安全的，但守卫完全依赖模板匹配；若一级界面下某个面板模板误命中，就可能按 ESC 反而**打开**菜单。本次未观察到误触发。

**优化方向**：恢复时把"当前已是一级界面"的判定做成强前置（例如同时要求输入态未被重置），或在按 ESC 前要求"面板模板命中且状态分类非 Primary"双条件。

### F4（需进一步验证）失败语义可能触发重复拉黑

业务层对部分路径使用"执行结果未知，请勿重复操作"的语义。若 UI 层在超时后误报成功，或调用方忽略"未知"而重试，存在重复执行风险。本次未在真机触发该路径，仅作记录。

## 7. 标准流程：恢复一级界面（纯原子命令组合）

内置流程在超时后都要"回到一级界面"。这个动作**不需要改代码**，用现有原子命令组合即可，但要遵守下面的顺序，否则会把界面推得更远。

### 组合规则

1. **第一步必须是 `activate`**。未激活时所有输入都会被前台闸门拒绝并报 `当前前台窗口不是目标游戏进程，已中止输入`——本次排查就踩过这个坑（游戏失去前台后 `press_key` 直接失败）。
2. 读取 UI 状态并**要求稳定**：连续两次读到同一个**非 `transition`** 状态才算稳定。
3. 稳定状态为 `primary*` → 完成。
4. 稳定状态为面板态（`secondary*` / `gamegate*` / `overworld*`）→ 发**一次** `press_key escape`，等待约 1500ms，回到第 2 步。
5. `transition:*` / `unknown` → 默认**不发送任何输入**，只等待后重读。
6. 但若未知态**连续 2 轮**仍不收敛，允许发**一次 ESC 探测**——有些页面（如玩家卡片）没有分类标签，纯日志判据会卡死，见 8.6。
7. ESC 总次数上限 5；超出则明确报告"未恢复"，不要继续盲按。

### 实测结果

从千星奇域菜单（应用分类器读作 `secondary:chat`）出发，**1 次 ESC** 即回到一级界面，并留下截图证据。

### 踩坑记录（重要）

第一版组合在 `transition:*` 上也发送 ESC，结果界面在 `secondary:chat` 与 `transition:primary:marker` 之间**来回振荡**，连按 6 次仍未恢复。

根因：**ESC 在一级界面是"打开菜单"的切换键**，不是"返回"键。因此判断必须在稳定态做出，且只在确认处于面板态时才发送。

### 现状与建议

- 当前只能靠"应用日志里的 `state=` 分类输出"或人工看截图来判定状态，**沙盒没有直接暴露 UI 状态查询**。
- 建议（未实现）：为沙盒增加一个只读的 UI 状态查询接口，让外部 AI 不必解析日志；以及把上述组合固化为一个原子命令，使恢复动作自带激活与稳定判定。

### 8.5 新发现：粘贴会静默丢失

同一套命令，**点击输入框后等待不足时粘贴会静默丢失**：命令全部返回成功，但输入框仍是占位文案、内容为空。等待约 700–900ms 后再粘贴即稳定生效。

危险点：拉黑流程若在此处静默失败，会带着空搜索继续往下走（或走到超时），属于**无错误上报的失败**。建议在流程内加入"粘贴后校验输入框非空"的断言。

### 8.6 新发现：玩家卡片页没有分类标签

打开玩家卡片时，应用分类器稳定输出 `friend=3ms back=10ms marker=69ms state=unknown`，主循环记为 `transition:unknown`，**持续十余秒不收敛**。

后果：只依赖 `state=primary*` 的恢复流程在该页面会一直"等待而不动作"，无法自行恢复。为此把恢复脚本升级为**有界探测**：未知态连续 2 轮后允许发一次 ESC 探测，总 ESC 次数仍设上限（详见第 7 节脚本）。

### 8.7 实测 ESC 分层（未启用千星布局）

`更多设置菜单` →(ESC) `玩家卡片` →(ESC) `搜索页` →(ESC) `一级界面`，即从菜单恢复到一级界面共 **3 次** ESC。
